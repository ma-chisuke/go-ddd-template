# 在庫コンテキストが発行するメッセージ契約

**このディレクトリは意図的に空です。** 在庫コンテキストは現在、クロスコンテキストの
メッセージ契約（コマンド / イベント）を 1 本も発行していません。未実装の穴ではなく、
現在の設計がそうなっているという事実の記録です。

この README があるのは、その事実を可視化するためです。git は空ディレクトリを追跡できないので、
このファイルが無ければ「在庫は発行元として存在するが、まだ何も発行していない」という状態と
「在庫という軸を作り忘れた」という状態を、リポジトリを見ただけでは区別できません。

## なぜ在庫は発行しないのか

在庫は注文の**下流**（Customer/Supplier の Supplier 側）にいます。注文が送る予約確定コマンド
（`ConfirmReservation`）と注文取消イベント（`OrderCancelled`）を購読して自分の状態を進めますが、
その結果を注文へ返すメッセージは持ちません。同期の照会は在庫の内部 HTTP 契約
（`contracts/api/inventory/internal.openapi.yaml`）を通り、注文の腐敗防止層（ACL）が呼び出します。

詳しくは [docs/context-map.md](../../../docs/context-map.md) を参照してください。

## 在庫がメッセージを発行するようになったら

1. このディレクトリに `<name>.schema.json` を追加します。封筒（envelope）の形と
   バージョニング方針は [../README.md](../README.md) にあります。
2. `type` の const は **`inventory.` で始めます**。ディレクトリ名（発行元コンテキスト）と
   `type` の接頭辞が一致することを `contracts/events/check-compat.sh` が機械検査します。
3. `$id` の末尾は `contracts/events/inventory/<name>.schema.json`（リポジトリ相対パス）に
   します。これも同じゲートが検査します。
